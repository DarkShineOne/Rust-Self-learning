# Модуль 2. Веб-разработка

Модуль переносит знания базового Rust в серверную разработку. Мы используем Axum и Tokio, но основное внимание уделяется не магии фреймворка, а границам приложения: HTTP DTO, доменные правила, репозитории, внешние клиенты и проверяемые ошибки.

## Последовательность

1. HTTP, JSON, валидация и архитектура.
2. PostgreSQL, миграции, транзакции и CRUD.
3. Аутентификация, middleware и авторизация.
4. Внешний HTTP API и S3-вложения.
5. Тестирование, наблюдаемость, OpenAPI и развёртывание.
6. Самостоятельная реализация итогового микросервиса по заготовкам.

## Итоговая архитектура

Public API `/api/public/v1` предназначен пользователям, private API `/api/private/v1` — модераторам и администраторам. Это разные роутеры и разные OpenAPI-контракты. В реальной инфраструктуре Nginx пропускает private API только из рабочей сети/VPN или через внутренний домен. Такая настройка является внешним допущением курса и не заменяет авторизацию в приложении.

PostgreSQL хранит доменные записи и метаданные файлов, S3 — содержимое вложений, внешний HTTP API получает уведомления для модераторов. Unit-тесты изолируют внешние системы интерфейсами и моками; integration-тесты работают с настоящими PostgreSQL и S3.

Готовой реализации итогового сервиса нет. Сигнатуры и тесты задают контракт, а реализация остаётся самостоятельной работой студента.
