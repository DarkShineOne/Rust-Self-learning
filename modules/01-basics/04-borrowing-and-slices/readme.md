# Заимствование, ссылки и срезы

## Цели

Научиться читать и изменять данные без передачи владения, различать `String`/`&str` и `Vec<T>`/`&[T]`, а также возвращать срезы, связанные с входными данными. Понять правила одновременного доступа по ссылкам.

## Неизменяемые ссылки

`&T` позволяет читать значение, не становясь владельцем:

```rust
fn length(text: &String) -> usize {
    text.len()
}

let text = String::from("feedback");
let size = length(&text);
println!("{text}"); // владение осталось здесь
```

После вызова `text` остаётся доступен. Такая ссылка не может пережить значение, на которое указывает.

Параметр `&String` работает, но для функции, которой нужен только текст, идиоматичнее `&str`: тогда принимаются и `String` через deref coercion, и строковые литералы, и срезы.

## Изменяемые ссылки

`&mut T` разрешает менять заимствованное значение:

```rust
fn add_exclamation(text: &mut String) {
    text.push('!');
}

let mut text = String::from("hello");
add_exclamation(&mut text);
```

Изменяемыми должны быть и исходная привязка, и создаваемая ссылка. `&mut` не передаёт владение и не создаёт копию.

## Правила одновременного доступа

В каждый момент можно иметь либо любое число неизменяемых ссылок, либо одну изменяемую, но не их конфликтующую комбинацию. Это предотвращает data race и чтение данных, которые одновременно меняются.

```rust
let mut value = String::from("a");
let first = &value;
let second = &value;
println!("{first}{second}");
let mutable = &mut value; // предыдущие ссылки больше не используются
mutable.push('b');
```

Non-Lexical Lifetimes (NLL) завершают заимствование после последнего фактического использования ссылки, а не обязательно в конце блока. Но если неизменяемая ссылка используется после изменения, компилятор отклонит код.

## Срезы

Срез `&[T]` содержит указатель на последовательность и длину. Он не владеет элементами. Аналогично `&str` — срез текста с гарантией корректного UTF-8.

```rust
let values = [10, 20, 30, 40];
let middle: &[i32] = &values[1..3];
assert_eq!(middle, [20, 30]);
```

Для изменяемого доступа существует `&mut [T]`. Функция может изменить элементы, но не длину исходного массива. Индексирование проверяет границы во время выполнения; итерация по срезу обычно удобнее.

`split_whitespace()` создаёт итератор подстрок, каждая из которых ссылается на исходный текст. `next()` возвращает `Option<&str>`; `Option` подробно разбирается в уроке 06, а в задании достаточно использовать `unwrap_or("")`, чтобы пустой вход дал пустую строку. Это не игнорирование ошибки: отсутствие слова является ожидаемым случаем.

## Возврат ссылки

Возвращаемая ссылка должна указывать на живой вход, а не на локальный `String`:

```rust
fn before_dash(text: &str) -> &str {
    match text.find('-') {
        Some(index) => &text[..index],
        None => text,
    }
}
```

Здесь `match` и `Option` используются как небольшая демонстрация; подробный разбор будет позже. Возвращённый срез имеет время жизни входа благодаря правилам elision. Явные lifetime-параметры рассматриваются в уроке 11.

## Deref coercion

Компилятор умеет преобразовывать `&String` в `&str`, а `&Vec<T>` в `&[T]` благодаря `Deref`. Поэтому публичные API обычно принимают наиболее общий заимствованный тип. Это не превращает ссылку во владение и не копирует данные.

## Типичные ошибки

- возвращать ссылку на локальную переменную;
- создавать `&mut` к неизменяемой привязке;
- удерживать читающую ссылку через конфликтующее изменение;
- принимать `&String` вместо более гибкого `&str`;
- выделять новый `String`, если контракт требует срез исходной строки.
