# Время жизни

## Цели

Понять, как компилятор связывает входные и выходные ссылки, когда нужны явные lifetime-параметры и почему они не продлевают жизнь значения. Научиться хранить ссылки в структурах без преждевременного перехода к owned-данным.

## Lifetime — отношение ссылок

Каждая ссылка имеет область, в которой она действительна. Обычно компилятор выводит её автоматически. Явный `'a` нужен не для управления памятью, а для описания отношения: «результат действителен, пока действительны оба входа».

```rust
fn shorter<'a>(left: &'a str, right: &'a str) -> &'a str {
    if left.len() <= right.len() { left } else { right }
}
```

Поскольку заранее неизвестно, какую ссылку вернёт функция, результат должен быть безопасен при любом выборе. Общее `'a` фактически ограничивается более коротким временем жизни аргументов на конкретном вызове.

Аннотация не заставляет строку жить дольше. Если владелец уничтожен, вызов не скомпилируется независимо от количества `'a`.

## Правила elision

Компилятор часто подставляет lifetimes сам:

1. каждый ссылочный параметр получает отдельный lifetime;
2. если входной lifetime ровно один, он присваивается всем выходным ссылкам;
3. при нескольких входных, если есть `&self` или `&mut self`, lifetime self присваивается выходным ссылкам.

Поэтому `fn first_word(text: &str) -> &str` не требует аннотации. В функции с двумя независимыми строковыми параметрами и возвращаемой ссылкой правил недостаточно: компилятор не знает, выбрать lifetime left, right или оба.

Третье правило удобно для методов, но иногда слишком ограничивает результат. Если метод возвращает ссылку на исходные данные, а не на поле самого wrapper, явный `'a` позволяет использовать результат после уничтожения wrapper.

## Ссылки в структурах

Структура с полем-ссылкой обязана объявить lifetime:

```rust
struct Line<'a> {
    content: &'a str,
}
```

Это означает: `Line` не может пережить текст, на который ссылается. Структура не становится владельцем текста. При перемещении `Line` копируется только ссылка, а строка остаётся у владельца.

`TextView<'a>` в задании хранит `&'a str`. Метод `first_line(&self) -> &'a str` намеренно возвращает lifetime исходного текста. Вариант `&self -> &str` по elision связал бы результат с заимствованием wrapper.

Если API должен пережить владельца текста, нужен owned `String` или другой владеющий тип, а не попытка обмануть lifetime.

## &'static str

`'static` означает, что ссылка может жить до конца программы. Строковые литералы имеют такой тип, потому что встроены в бинарник. Это не делает любую строку static и не требуется большинству приложений.

Требование `T: 'static` в потоках часто означает отсутствие не-static заимствованных ссылок, а не то, что значение обязано существовать с начала программы. Owned `String` удовлетворяет такому ограничению.

## Lifetime и коллекции

`Vec<&'a str>` владеет только набором ссылок, а не строками. Его можно вернуть из функции, если исходный текст переживёт Vec. При пустой подстроке поиска поведение должно быть определено отдельно: в нашем задании каждая строка содержит пустую подстроку, поэтому возвращаются все строки.

Метод `str::lines()` учитывает стандартные line terminators и не создаёт новый `String`. CRLF обрабатывается как line ending, поэтому возвращаемые строки не содержат завершающий `\r`.

## Lifetime subtyping и bounds

Более длинный lifetime может использоваться там, где требуется более короткий, если отношения типов это допускают. Bounds вида `T: 'a` утверждают, что ссылки внутри `T` живут не меньше `'a`. Это отличается от `&'a T` — ссылки на значение `T` на область `'a`.

Для текущего курса важно читать такие записи, а не усложнять API без необходимости. Обычно компилятор подсказывает отсутствующую связь, но сначала проверьте логику владения: не любая ошибка исправляется добавлением `'static`.

## Типичные ошибки

- добавлять `'static`, чтобы заставить ссылку жить дольше;
- возвращать ссылку на локальный `String`;
- связывать результат со `&self`, когда нужен lifetime исходного текста;
- выделять owned копии там, где достаточно среза;
- считать lifetime параметром времени в секундах или runtime-блокировкой.
