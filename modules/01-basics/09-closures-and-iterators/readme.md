# Замыкания и итераторы

## Цели

Научиться преобразовывать коллекции цепочками итераторов, понимать ленивость и передавать поведение через замыкания. Отдельно разобрать, когда результат заимствует исходные данные, а когда создаёт новую коллекцию.

## Iterator и IntoIterator

Итератор реализует `Iterator::next() -> Option<Self::Item>`. Цикл `for` использует `IntoIterator`, чтобы получить итератор из коллекции или диапазона.

```rust
let ratings = [3, 5, 4];
let total: u8 = ratings.iter().copied().sum();
```

Для среза `.iter()` выдаёт `&T`, поэтому `sum()` для чисел часто требует `.copied()`. `.cloned()` клонирует элементы и отличается от Copy; `.map(|item| item.rating)` извлекает Copy-поле через ссылку.

`into_iter()` потребляет `Vec` и выдаёт owned-значения. Для массива современный Rust также создаёт owned-итератор при вызове в owned-контексте. Всегда смотрите на тип `Item`, если цепочка не компилируется.

## Ленивые адаптеры

`map`, `filter`, `take`, `skip`, `enumerate`, `flat_map` и другие адаптеры обычно не выполняют работу до потребления итератора. Потребители: `collect`, `sum`, `count`, `fold`, `for_each`, `find`, `any`.

```rust
let titles: Vec<String> = vec![String::from("one"), String::from("two")]
    .iter()
    .filter(|title| !title.is_empty())
    .map(|title| title.to_uppercase())
    .collect();
```

Без `collect` не появится `Vec`. Ленивость позволяет `take(5)` не обрабатывать бесконечный остаток, но не означает автоматическую оптимизацию любой логики.

`filter` сохраняет исходный порядок. `map` не меняет число элементов, `filter_map` одновременно преобразует и отбрасывает `None`.

## collect и тип результата

`collect` обобщён и требует известного целевого типа. Его указывают аннотацией, турбофишем или выводом из возвращаемой сигнатуры:

```rust
let lengths: Vec<usize> = titles.iter().map(String::len).collect();
```

Из итератора пар можно собрать `HashMap`, из строк — `Vec<String>`, из `Result` — `Result<Vec<_>, _>`. Возможность собрать тип определяется реализацией `FromIterator`.

## fold и агрегация

`fold(initial, |acc, item| next_acc)` универсален, но специализированные `sum`, `count`, `max` читаются лучше. Для среднего нужны одновременно сумма и количество; пустая группа возвращает `None`, а не выполняет деление на ноль.

`reduce` возвращает `Option`, потому что у него нет начального значения. Выбирайте агрегат по поведению на пустом входе.

## Замыкания

Замыкание — значение с анонимной логикой и окружением:

```rust
let minimum = 4;
let positive = ratings.iter().filter(|rating| **rating >= minimum);
```

Компилятор выводит способ захвата по использованию: ссылка, изменяемая ссылка или перемещение. Ключевое слово `move` заставляет захватить окружение по значению, что особенно важно для потоков и возвращаемых замыканий.

## Fn, FnMut и FnOnce

- `Fn` вызывается многократно и не изменяет захваченное состояние;
- `FnMut` может изменять окружение;
- `FnOnce` может потребить окружение и поэтому обещает лишь возможность одного вызова.

Любой тип, реализующий `Fn`, реализует также `FnMut` и `FnOnce`, но не наоборот. Параметр `impl FnMut(&Feedback) -> bool` в задании — удобная форма generic-параметра; полное объяснение `impl Trait` и generics будет в уроке 10.

Передача замыкания не означает вызов. Функция `count_matching` должна сама передать каждую заимствованную запись в predicate.

## Заимствованный результат

`positive_titles` возвращает `Vec<&str>`. Сам Vec новый, но строки принадлежат исходному срезу. Пока используются эти ссылки, исходные данные должны жить. Клонирование title изменило бы тип результата и скрыло лишнюю аллокацию.

## Типичные ошибки

- забыть потребитель после `map`;
- использовать `item.field` и случайно переместить поле из ссылки;
- путать `.iter()` и `.into_iter()`;
- сортировать `Vec<&T>` там, где нужен owned результат;
- передавать захватывающее замыкание там, где сигнатура принимает только fn pointer.
