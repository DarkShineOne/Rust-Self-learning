# Коллекции и строки

## Цели

Научиться выбирать коллекцию по операциям и порядку, использовать `entry`, перемещать значения из `Vec` в индекс и корректно говорить о байтах, `char` и пользовательских символах.

## Vec

`Vec<T>` — владеющий динамический массив в куче. Элементы одного типа расположены последовательно. `push` добавляет в конец, `pop` возвращает `Option<T>`, `len` и `is_empty` описывают текущее число элементов, `capacity` — выделенное место.

```rust
let mut ratings = Vec::new();
ratings.push(5);
ratings.extend([3, 4]);
assert_eq!(ratings.len(), 3);
```

Индекс `ratings[i]` паникует вне границ, а `ratings.get(i)` возвращает `Option<&T>`. Изменение длины может переместить буфер, поэтому нельзя удерживать ссылку на элемент через `push`, который конфликтует с заимствованием.

`&Vec<T>` обычно заменяется на `&[T]` в параметрах. Если функция должна забрать элементы и больше не нуждается в исходном Vec, принимайте `Vec<T>` и используйте `into_iter()`.

## HashMap и HashSet

`HashMap<K, V>` обеспечивает поиск по хешируемому ключу. `HashSet<T>` — множество уникальных значений на той же основе. Порядок обхода не является стабильным контрактом.

```rust
use std::collections::HashMap;
let mut counts = HashMap::new();
counts.insert("bug", 1);
assert_eq!(counts.get("bug"), Some(&1));
```

Ключ должен реализовывать `Eq` и `Hash`. Важно, чтобы равные ключи имели одинаковый hash. Изменение ключа, находящегося в map, через внутреннюю изменяемость может нарушить логику коллекции.

Метод `insert` возвращает старое значение и заменяет его новым. Поэтому поведение при дубликатах нужно выбирать явно: запретить, сохранить первое или последнее.

## Entry API

`entry` позволяет проверить и изменить значение без повторного поиска:

```rust
let count = counts.entry("idea").or_insert(0);
*count += 1;
```

`or_insert`, `or_insert_with`, `and_modify` и `or_default` покрывают типичные агрегации. `or_insert_with` полезен, когда создание default имеет стоимость и должно выполняться только для отсутствующего ключа.

## BTreeMap и BTreeSet

B-tree коллекции хранят ключи по порядку `Ord`. Их асимптотика и характеристики отличаются от hash-коллекций, зато обход детерминирован и поддерживаются диапазоны. `BTreeSet` подходит домашнему заданию, потому что результат должен быть отсортирован.

Выбирайте структуру по требованиям, а не только по средней сложности O(1): порядок, диапазоны, ключи и частые операции влияют на дизайн API.

## String и &str

`String` владеет корректным UTF-8 буфером, `&str` заимствует такой текст. Методы `push_str`, `insert` и `to_lowercase` имеют разные требования к владению и аллокациям.

`to_lowercase()` может создать несколько кодовых точек для одной исходной, поэтому результат — новый `String`. Unicode-aware `is_alphanumeric` удобен для учебного разделения слов, но это не полноценный алгоритм естественного языка.

## Байты, char и grapheme clusters

```rust
let text = "ё";
assert_eq!(text.len(), 2);
assert_eq!(text.chars().count(), 1);
```

`len()` — байты, `chars()` — Unicode scalar values, представленные `char`. Пользовательский видимый символ может состоять из нескольких `char`, например буквы и комбинируемого диакритического знака. Для grapheme clusters нужна специализированная библиотека; стандартный `char` этого не обещает.

Нельзя индексировать `String` как `text[0]`: один байт не обязан быть символом. Диапазоновая индексация `&text[..n]` требует UTF-8 boundary и паникует при её нарушении.

## Итерация и владение

- `.iter()` заимствует элементы;
- `.iter_mut()` выдаёт изменяемые ссылки;
- `.into_iter()` потребляет коллекцию и выдаёт owned-элементы для владеющих коллекций.

При построении `HashMap<u64, FeedbackRecord>` из `Vec<FeedbackRecord>` потребление Vec позволяет переместить записи без Clone. Подробно адаптеры итераторов разбираются в следующем уроке.

## Типичные ошибки

- ожидать упорядоченный обход `HashMap`;
- использовать `len()` строки как число символов;
- клонировать записи вместо `into_iter`;
- выполнять два поиска там, где подходит `entry`;
- выбирать `HashSet`, когда тесты и API требуют сортировку.
