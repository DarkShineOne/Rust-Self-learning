# Обобщения и трейты

## Цели

Научиться создавать обобщённые функции, ограничивать их возможностями трейтов и выделять абстракции хранилища. Понять различие associated type, generic trait, статической и динамической диспетчеризации.

## Generics

Обобщённый параметр позволяет одной сигнатуре работать с разными типами:

```rust
fn first<T>(items: &[T]) -> Option<&T> {
    items.first()
}
```

`T` не означает «любое значение с любыми операциями». Внутри функции доступны только операции, гарантированные ограничениями. Для `first` ничего кроме ссылки не нужно, поэтому ограничений нет.

При статической диспетчеризации компилятор создаёт специализированные версии для конкретных типов — мономорфизацию. Это обычно устраняет виртуальный вызов, но увеличивает объём кода и требования к известности типов при компиляции.

## Traits и bounds

Трейт описывает поведение:

```rust
trait Summary {
    fn summary(&self) -> String;
}
```

Generic bound `T: Summary` разрешает вызвать `.summary()`. Несколько ограничений объединяются `T: Summary + Clone` или выносятся в `where`. Используйте минимально необходимый набор bounds: лишний `Clone` сужает API без пользы.

Трейты могут содержать default methods, константы, associated types и супертрейты. Реализация для собственного типа записывается через `impl Trait for Type`.

## Associated types

```rust
trait Store {
    type Error;
    fn save(&mut self) -> Result<(), Self::Error>;
}
```

Associated type выбирается реализацией. Он подходит, когда конкретная реализация трейта имеет один естественный тип ошибки. Generic trait `Store<E>` позволяет одной реализации потенциально существовать для нескольких `E` и выражает другое отношение.

В `Iterator` associated type `Item` задаёт тип выдаваемых значений. В `Repository` тип `Error` отделяет API контракта от конкретной ошибки памяти или SQL.

## impl Trait и dyn Trait

`impl Trait` в параметре означает обобщённый конкретный тип, скрытый сигнатурой. В возвращаемой позиции он означает один конкретный тип реализации, выбранный функцией, хотя вызывающий код знает только трейт.

`dyn Trait` — trait object с динамической диспетчеризацией:

```rust
fn print_summary(value: &dyn Summary) {
    println!("{}", value.summary());
}
```

Trait object позволяет хранить разные реализации за одним типом ссылки, но имеет ограничения object safety и косвенный вызов. `Box<dyn Trait>` владеет объектом, `&dyn Trait` заимствует. `Arc<dyn Trait>` появится в архитектуре веб-приложения.

Generic `Repository` с associated type нужно уточнять как `dyn Repository<Error = RepositoryError>`.

## Реализация репозитория

`MemoryRepository` хранит записи по id. Трейт отделяет операции от структуры:

- `insert` не должен перезаписывать существующий id;
- `update` не должен создавать отсутствующую запись;
- `delete` возвращает удалённое значение, передавая владение;
- `get` возвращает ссылку, связанную с хранилищем.

Важно проверять ошибку до мутации. `HashMap::entry` помогает атомарно выразить проверку и вставку относительно заимствования map.

`values` возвращает ссылки и отдельно сортирует их по id. Это не меняет внутреннюю HashMap и даёт детерминированный результат.

## Обобщённый поиск

`find_max_by_key` разделяет тип элемента `T`, тип ключа `K` и замыкание `F`. `K: Ord` нужен для сравнения, `F: FnMut(&T) -> K` — для получения owned-ключа из ссылки. Возвращается ссылка на исходный элемент, поэтому `Clone` для `T` не требуется.

При равных максимальных ключах контракт сохраняет первый элемент. Стандартные методы поиска максимума могут иметь другое правило выбора последнего, поэтому читайте документацию, а не переносите поведение по памяти.

## Стандартные трейты и coherence

`Debug`, `Display`, `Clone`, `Copy`, `PartialEq`, `Eq`, `Hash`, `Ord`, `From`, `Into`, `Default`, `Drop`, `Deref` формируют общий словарь экосистемы. `Display` предназначен для пользовательского представления, `Debug` — диагностического.

Orphan rules ограничивают реализацию чужого трейта для чужого типа: обычно хотя бы трейт или тип должен быть локальным. Это защищает от конфликтующих реализаций между crate.

## Типичные ошибки

- требовать `Clone` там, где возвращается ссылка;
- выбирать `dyn Trait` без необходимости гетерогенности;
- путать generic trait и associated type;
- ожидать, что `impl Trait` в return позволяет возвращать разные несвязанные типы из веток;
- игнорировать правило выбора при равных ключах.
